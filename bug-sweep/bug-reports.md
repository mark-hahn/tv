# Bug Sweep Reports

1. apps/down/src/movie-rsync.js:25 - Completed and failed movie copy jobs remained in the module-level jobs map forever, so a long-running downloader could grow memory without bound. Severity: medium. Risk: finished movie jobs now disappear after 10 minutes or when more than 50 finished jobs are retained, so very old completed entries no longer appear in /movieDownloads. Resolution: fixed by timestamping terminal job states and pruning finished jobs while preserving active downloads.

2. apps/down/src/main.js:2547 - When TVDB search requests failed 15 times, chkTvDB returned without advancing to the next file or clearing the scan cycle, so the downloader could remain stuck with cycleRunning true. Severity: high. Risk: after the retry cap, the current file is skipped until a later cycle instead of blocking the whole scan. Resolution: fixed by treating 15 or more TVDB request errors as the cap and continuing with checkFile.

3. apps/api/src/server.js:1154 - /api/local/mediainfo accepted absolute or escaping relPath values via path.join, allowing mediainfo/ffprobe to run outside the selected media root. Severity: high. Risk: requests with absolute paths or .. segments are now rejected with HTTP 400. Resolution: fixed by validating relPath and enforcing resolved-path containment under the chosen media root.

4. apps/api/src/local.js:38 - Local rename and move-to-trial helpers only checked for literal ".." and built paths by concatenation, so absolute or slash-edge inputs could escape the intended media roots. Severity: high. Risk: stricter validation now rejects absolute paths, NULs, parent-directory segments, and destination names containing path separators. Resolution: fixed by resolving all relative inputs under the selected root and enforcing containment before rename.

5. apps/api/src/search-worker.js:8 - The forked search worker called process.send directly, so a disconnected IPC channel could turn a handled search result or error into an uncaught worker exception. Severity: low. Risk: if the parent is gone, the worker now exits without delivering the final payload. Resolution: fixed by adding a guarded sendAndExit helper that checks process.connected and catches send failures.

6. apps/api/src/usb.js:682 - USB rename/delete helpers only rejected literal ".." and built remote paths by concatenation, so absolute or slash-edge inputs could target outside the intended USB roots. Severity: high. Risk: stricter validation now rejects absolute paths, NULs, parent-directory segments, and destination names containing path separators. Resolution: fixed by resolving UI paths as root-relative POSIX paths before running remote mv/rm.

7. apps/srvr/src/fileOps.js:84 - Server delete helpers accepted slash-containing paths as-is, and season deletion accepted showPath as-is, so absolute or relative paths could delete outside /mnt/media/tv. Severity: high. Risk: deletePath now refuses the TV root and rejects paths outside /mnt/media/tv, including parent-directory escapes. Resolution: fixed by resolving all delete/show paths under the TV root and enforcing containment before rm/rimraf.

8. apps/srvr/src/routes/media.js:264 - /api/stream decremented the active video stream counter in both ffmpeg error and exit handlers, so a spawn failure or error+exit sequence could drive the stream count negative and leave the header status wrong. Severity: low. Risk: none beyond making the counter update idempotent. Resolution: fixed by using a one-time decrement guard like the subtitle stream handlers already use.

9. apps/srvr/src/util.js:30 - PST timestamp helpers did not normalize an Intl hour value of 24 to 00, which violates the app timestamp convention and can produce invalid-looking times such as 24:43. Severity: low. Risk: only formatted timestamp strings change from 24:xx to 00:xx. Resolution: fixed by normalizing PST time strings in toPstDateTime and getPstDate.

10. apps/srvr/src/disk.js:96 - The probed raw-height ffprobe cache stored every probed video path forever, so repeated full-library scans across a large or changing library could grow memory without bound. Severity: medium. Risk: after 10000 distinct paths, the oldest cached height is evicted and may be probed again later. Resolution: fixed by capping the cache and evicting the oldest entry before adding a new one.

11. apps/srvr/src/loid.js:44 - saveAndVerifyLoid wrote the loid cookie and fetched Reddit without a catch, so disk or network failures could reject through the request path instead of returning the expected error object. Severity: medium. Risk: failed saves/verifications now return an error response and leave loidNeeded unchanged. Resolution: fixed by catching write/fetch failures and logging through logHere.

12. apps/srvr/src/routes/media.js:278 - /api/stream did not handle ffmpeg stdout pipe errors, so a response pipe failure could leave the ffmpeg process running until another close path fired. Severity: medium. Risk: stdout pipe errors now terminate the ffmpeg process. Resolution: fixed by adding a stdout error handler that logs and calls the existing killFfmpeg cleanup.

13. apps/tv/src/main.js:20 - The TV app opened data/tv-adb.log without ensuring the data directory existed, so a missing directory could make the write stream fail at startup; its timestamp formatter also did not normalize hour 24. Severity: medium. Risk: creates apps/tv/data when missing and changes any 24:xx:xx ADB log timestamp to 00:xx:xx. Resolution: fixed by creating the data directory before opening the stream and normalizing the formatted log line.

14. apps/tv/bravia.js:129 - The Bravia CLI sent every service call, including media_player.turn_on/off/volume/select_source, to notify.bravia_k_65xr70 instead of the Bravia media_player entity, so most commands could fail or target the wrong domain. Severity: high. Risk: notify still targets notify.bravia_k_65xr70, while media_player commands now target media_player.bravia_k_65xr70. Resolution: fixed by selecting the target entity based on the command domain.

15. apps/asr/asr.js:43 - When creating the default ASR tmp directory failed, the code created a /tmp fallback directory but did not assign tmpDir to it, so later processing still used the unavailable original path. Severity: high. Risk: only failure fallback behavior changes. Resolution: fixed by assigning tmpDir to the created fallback directory.

16. apps/android/App.js:385 - The Android app's WebSocket onclose handler always scheduled a reconnect, even if the closing socket was stale and wsRef already pointed at a newer socket, which could create duplicate live connections and duplicate remote-action echoes. Severity: medium. Risk: stale sockets no longer reconnect after a replacement socket exists. Resolution: fixed by ignoring stale onclose events and clearing wsRef only for the current socket.

17. apps/client/src/srvr.js:84 - The web client's WebSocket close/error handlers were attached to a mutable module-level ws reference, so a stale socket could reject calls or start a reconnect after a newer socket existed. Severity: medium. Risk: stale socket events are ignored instead of affecting the current connection. Resolution: fixed by capturing the socket when handlers are attached and checking it before close/error handling.

18. apps/client/src/components/trailer.vue:548 - The trailer component registered window.onYouTubeIframeAPIReady and created YouTube player instances but did not clear the global callback or destroy players on unmount, so remounts could leak player objects and call back into a destroyed component. Severity: medium. Risk: leaving the trailer pane now stops any active embedded playback during unmount. Resolution: fixed by saving/destroying players and deleting the global callback when it belongs to this component.
