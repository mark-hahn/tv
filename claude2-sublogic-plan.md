# New subtitle logic: plan

Nothing has been built yet. This is the agreed plan, in the order the pieces
depend on each other.

## Principles

- Every subtitle is a sidecar file next to its video. Embedded tracks are
  never shown; once a text track has been copied out, the embedded one is
  treated as not existing.
- Every subtitle file written, anywhere and for any reason, goes through the
  full sanitizer first.
- Nothing is ever downloaded from OpenSubtitles except just before a video
  plays.
- Chksrt no longer exists: no pane, no queue, no history, no snooze.
- Movies get no subtitle processing.

## Subtitle types

- T is a text track copied out of the video. H is the same for a track
  flagged as describing music and sound.
- V is a file downloaded from OpenSubtitles, named with its five-character
  tag.
- S is any other subtitle file that arrived beside the video.
- Plus (+) is a file generated by ASR.
- Image-based (PGS) and forced embedded tracks are never copied out, so they
  are never shown.
- Legacy files keep their names. The old copies of embedded tracks count as
  T, and every other legacy file counts as S.

## What is stored

A new database, written only by tv-srvr, holds three things.

- Every OpenSubtitles search result ever returned, one record per subtitle
  file. Each record carries the show, season and episode, the file id, the
  fields the same-origin rules need, a downloaded flag and a chosen flag.
- The subtitle that was showing when each episode last stopped, with its
  type. This is what lets a choice of T, H, S or plus carry to the next
  episode, since the chosen flag only exists for downloaded files.
- The list of videos the add-to-disk steps have already handled, so the
  sweep does not repeat them.

## When a video starts

This is the same for tvapp and for the web player.

1. The server finds the episode's video.
2. If fewer than three subtitles have been downloaded for the episode, it
   searches OpenSubtitles and stores any new results. Results whose file is
   already on disk from before are marked as downloaded. With three or more
   already downloaded there is no search.
3. It then downloads until the episode has three or no candidate is left.
   A candidate is never a file already downloaded. The first choice is a
   result from the same origin as a chosen file of the show. Failing that, it
   is the first result that is neither hearing-impaired nor foreign-parts-only.
   Failing that, nothing is downloaded.
4. The video waits at most four seconds for this. If it is not finished by
   then, or a search or download fails, the video starts anyway and a pop-up
   error appears on the phones and in the web tv pane. A failed download is
   skipped for the next candidate. Downloads still running finish in the
   background and are there for the next play.
5. The player is given only the video's sidecar files, each with its type
   letter, and told which one to start on.

## Which subtitle a video starts on

1. The file chosen for this episode, if there is one.
2. Otherwise the type last chosen for the show. For a downloaded file that
   means the one from the same origin as a chosen file.
3. Otherwise the first one available, in the order T, H, V, S, plus.
4. With no sidecar at all, subtitles are off.

## When a video stops

- The player reports which subtitle file was showing.
- That file becomes the chosen one for the episode, and the episode's other
  files stop being chosen. Its type becomes the show's last chosen type.
- A stop in the first few seconds, which already counts as never played,
  changes nothing.
- A switch made in the subtitle panel during play therefore sticks, because
  it is what is showing at the stop.

## Same-origin rules

Two search results for different episodes of a show are from the same origin
when all of the following hold.

- The hearing-impaired, HD, foreign-parts-only, AI-translated and
  machine-translated flags are all equal, and the frame rates are equal
  unless either is zero, which means unknown.
- If the uploader is a real person, the uploader is the same and the two
  upload dates are within one hour.
- If the uploader is anonymous or one of the site's shared bot accounts, the
  uploader and date are ignored. Instead the release names must be equal once
  the episode number and episode title are removed, or the comments must be
  equal and not empty.

## When a video or an S file is added to disk

The file watcher puts the video in the existing subtitle queue, which does
these steps in order.

1. Copy each English or untagged embedded text track to a sanitized T or H
   file, numbered by the track's index in the video. A track that already has
   a legacy copy is skipped.
2. Rename a newly arrived S file to an S name with the next free number,
   sanitizing it on the way. It belongs to the video in the same folder with
   the same season and episode. One with no such video is left alone.
3. If the video replaced an older one of the same episode, copy the old
   video's subtitle files to the new video's name, sanitized, without
   overwriting anything.
4. Search OpenSubtitles for the episode and store the results. Nothing is
   downloaded.
5. Put the video in the ASR queue when it has no embedded T or H track, the
   search gave nothing usable under the choosing rules, and it has no ASR
   file yet. A video with only image-based subtitles therefore goes to ASR.

## The sweep

- The six-hourly sweep stays, as the second route for anything the watcher
  misses and as the way the existing library gets handled.
- It only takes videos that have no sidecar subtitle file at all, in any
  library show, watched or not, and that have not been handled before.
- For those it runs the same steps as an added video, so their embedded T
  and H tracks are copied out.
- A video that already has any sidecar is left exactly as it is. Its
  embedded tracks are not copied out and so never show.
- The sweep never sends an already-watched episode to ASR, because ASR is a
  paid service. Newly added videos follow the ASR rule exactly.
- Next-up and unwatched episodes are done first. The whole library will take
  hours at idle priority, and until a video with no sidecars is reached it
  plays with no subtitles.

## Sanitizing

There are six places a subtitle file gets written, and all six sanitize.

- Embedded tracks copied out. Today a track that needs no cleaning is not
  written at all; that is a bug and it gets fixed, since the copy is now the
  only way the track can show.
- Downloads. Today these only have formatting stripped.
- S files being renamed.
- Files copied to a replacement video.
- ASR output. The sanitizer moves to the shared package so the ASR app can
  use it before it writes.
- The timing Apply in the subtitle panel, which rewrites the file.

## What is removed

- On the server: everything chksrt (queue, review endpoints, history,
  snooze, the marker that recorded an embedded choice, the header count);
  the subtitle scan and the OpenSubtitles check inside the tvdb update; the
  bulk search, count, delete and offset endpoints for OpenSubtitles files;
  the daily download counter and check history; the unused per-episode
  subtitle listing; and the old batch download script.
- In the web client: the Chksrt button and its count, the chksrt mode of the
  video player, the Subs button in the info pane, the ChkSrt tab in the
  queues pane, and the chksrt enqueue in the map pane.
- Intro stills were prebuilt for shows waiting in the chksrt queue; they are
  now prebuilt only for shows flagged as needing an intro.

## What is kept

- The ASR queue, its processing, and the ASR button in the local pane.
- The Subs button in the local pane, which now runs the add-to-disk steps on
  the selected videos.
- The subtitle panel in tvapprc mode on the phone and the web tv pane,
  including its timing Apply, which now works on every row because every
  subtitle is a file.
- The video player's intro and simple modes.
- The separate OpenSubtitles search in the torrent API server, which is not
  file processing.
- On disk: every existing sidecar, the old embedded-choice markers, and the
  old chksrt data files. None of them are read any more except the sidecars.

## Client changes

- tvapp lists only sidecar tracks, starts on the server's pick, turns
  subtitles off when there is none, and reports the showing file with its
  progress reports.
- The web player gets the same list and pick and makes the same report.
- The subtitle panel on the phone and in the web tv pane labels each row
  with its type letter and number or tag.
- The phone and the web tv pane get the new pop-up for a subtitle download
  error, delivered the same way as the existing unwatched-episode warning.

## Documentation

After the code is in, the project instructions are updated and mirrored to
the copilot instructions: the two subtitle bullets in the tvapp summary are
rewritten, its date is moved, and a new Subtitles section records the type
letters, the principles above, the stored lists, the play-time rule, the
choosing and same-origin rules, the add-to-disk steps and the sweep.

## Order of work

1. Server, deployed on its own, followed by a check of the logs for
   restarts.
2. ASR app, deployed on its own, for the sanitizer.
3. tvapp, built and installed.
4. Web client and web player.
5. Phone app. Whether it is running through Metro is checked before any
   build.
