
# handle mutiple clients logging
- if 2 clients are running at once then their unilog events will be jumbled and useless
  - we need to identify the clients and make sure only one is logging at a time
- each client should generate a guid hash when loaded
  - it should send the hash with each log event 
- keep a map with the hash as the key and a value that is a unique client id 
- when a client log event is received look up the client id in the hash:
  - if the hash is new:
    - add the client hash to the map with a new id = last id + 1
    - save the new id in a var curClientLogId
    - add a unilog event `New client <new id>` to the db 
      - add event with a level of `warn` and a group of `clients`
    - add the event the client sent to the db
      - the client event must be first because it divides the events between clients
  - if the hash is old and the id == curClientLogId then:
    - add the event the client sent to the db
    - this is the standard client logging
  - if the hash is old and the old id != curClientLogId:
    - ignore the event the old client sent
    - return an error response to the client
- when a client receives an error response:
  - it should show a message in the hdrmsg bar at the top of list.vue
  - the hdrmsg bar background should be light red
  - the message and background should be permanent until the client is reloaded
