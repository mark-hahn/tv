# Ideas for Adding Year Priority to `smartTitleMatch`

## 1. Implicit Extraction & Filtering (Magic)
*   **Concept**: The function automatically extracts a 4-digit year from the input `title` string (e.g., "The Office (2005)").
*   **Requirement**: Candidate objects in `titleArray` must have a recognizable year property (e.g., `year`, `startYear`, `releaseDate`) OR contain the year in their string representation.
*   **Logic**:
    1.  Regex extract `(19|20)\d{2}` from the query title.
    2.  If a year is found, create a "preferred" subset of candidates that match that year.
    3.  If the preferred subset is not empty, run the name matching logic (Exact -> Levenshtein) ONLY on that subset.
    4.  If the subset is empty (or no year in query), run logic on the full list.
*   **Pros**: Backward compatible if implemented carefully; "just works" for strings like "Show (Year)".
*   **Cons**: Relies on guessing which property holds the year in candidate objects (`.year`? `.startyear`? `.release_date`?).

## 2. Explicit Year Argument (Clear & Robust)
*   **Concept**: Change signature to `smartTitleMatch(title, titleArray, options)`.
*   **Usage**: `smartTitleMatch("The Office", candidates, { year: 2005 })`.
*   **Logic**:
    *   If `options.year` is present, filtering happens explicitly before name matching.
*   **Pros**: Deterministic. Callers usually already have the year separated (e.g., from TMDB response or folder structure).
*   **Cons**: Requires changing call sites to pass the extra data.

## 3. Weighted Scoring System (Fuzzy)
*   **Concept**: Abandon the "Pass 1, Pass 2" stage approach for a single scoring pass.
*   **Logic**:
    *   Assign points for specific criteria:
        *   Exact Name Match: +100
        *   Fuzzy Name Match: + (100 - LevenshteinDistance * 5)
        *   Year Match: +50
    *   Return the candidate with the highest total score.
*   **Pros**: Handles nuance better (e.g., "Perfect name match but missing year info" might beat "Wrong name but correct year").
*   **Cons**: Harder to debug why a match happened; complex to tune weights.

## 4. Standardized Candidate Interface (Clean Code)
*   **Concept**: Enforce a strict structure for `titleArray`.
*   **Logic**:
    *   `titleArray` must contain objects matching `{ title: string, year?: number|string }`.
    *   Caller is responsible for mapping their data (TMDB, Rotten, etc.) to this format before calling.
*   **Pros**: Keeps the utility simple and logic-free regarding "how to find the year property".
*   **Cons**: Adds work for every caller to `.map()` their data first.

## Recommendation
**Option 2 (Explicit Options)** is likely the best balance. It keeps the function pure but allows the caller to provide the critical disambiguation context without relying on string parsing magic inside the matching utility.

Example wrapper for Option 2:
```javascript
export function smartTitleMatch(title, candidates, { year } = {}) {
   let pool = candidates;
   
   // Optional optimization: Filter pool by year first if provided
   if (year) {
      const yearMatches = pool.filter(c => getCandidateYear(c) == year);
      if (yearMatches.length > 0) pool = yearMatches;
   }
   
   // ... proceed with name matching on `pool` ...
}
```
